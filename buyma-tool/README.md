# BUYMA出品支援ツール（低価格版）

開発指示書「BUYMA出品支援ツール（低価格版）開発指示書」の §9 開発の順番に沿って作っています。

| 段階 | 内容 | 状態 |
|---|---|---|
| 1 | Chrome拡張：商品ページから情報と画像URLを取る（タオバオ・天猫は専用の読み取り、それ以外は AI で読み取り） | できた |
| 2 | サーバー側でClaude APIを使ってタイトル・説明文を作り、価格計算をつなげる | できた |
| 3 | CSVとZIPの出力（＋BUYMA の項目ごとにコピー。登録はユーザー本人が行う半自動） | できた |
| 4 | ログイン・データベース・使った回数の管理 | できた |
| 5 | Stripeでの課金と無料お試し（＋紹介制度） | できた |
| 6 | ホームページと規約のページ（＋FAQ・無料ガイド・ブログ） | できた（規約はたたき台） |
| 7 | 自分の出品で実際に使ってテスト → 少人数に先行で公開 | **あなたの作業**：[docs/LAUNCH_CHECKLIST.md](docs/LAUNCH_CHECKLIST.md) |

後から足す機能（指示書 §3-5：在庫・価格の変更チェック、チーム利用）はまだ作っていません。1688 は、どのサイトでも使える AI の読み取りで扱えます（専用の読み取りはまだ）。

## 全体の形

```
buyma-tool/
  extension/   Chrome拡張（ユーザーのブラウザで動く。商品ページの読み取り・BUYMA 出品用データの表示とコピー）
  web/         ホームページ＋管理画面＋API（Next.js。Vercel に公開）
    src/app/       画面と API
    src/lib/       価格計算・プラン・AI・禁止ワードなどの中身
    supabase/      データベースの設定（SQL）
    tests/         サーバー側のテスト（npm test）
  docs/        公開までの手順・費用の試算・公開前チェックリスト
  tests/       拡張機能のテスト（npm test）
```

- 公開までの手順：[docs/SETUP.md](docs/SETUP.md)
- AI の費用とプランの利益：[docs/COST.md](docs/COST.md)
- 公開前チェックリスト：[docs/LAUNCH_CHECKLIST.md](docs/LAUNCH_CHECKLIST.md)

## Chrome拡張（extension/）

```
extension/
  manifest.json          Manifest V3
  background.js          ログイン連携の受け取りだけ（BUYMA の画面は操作しない）
  popup.html/js/css      ツールバーのボタンを押したときの画面（読み取り → 確認・修正 → BUYMA に貼る内容）
  options.html/js        設定画面（サーバーURL、画像の大きさ）
  src/page-reader.js     どのサイトでも使える読み取り（本文・JSON-LD・画像の候補をまとめる。DOMを読むだけ）
  src/extractor.js       タオバオ／天猫専用の読み取り（全部取れれば AI を使わずに済む）
  src/product-form.js    確認・修正画面と商品データの行き来、「全部まとめてコピー」の文章
  src/api.js             サーバーのAPIを呼ぶ道具（トークンの保存・自動更新）
  src/zip.js             ZIPを作る道具（外部ライブラリなし）
  src/images.js          画像を取り、大きさをそろえてZIPにする
tests/
  fixtures/              見本のページ（タオバオ・天猫・韓国の通販サイト・ヨーロッパの通販サイト・ログイン画面）
  *.test.js              テスト
```

### しくみ：半自動（BUYMAへの登録はご自身で）

BUYMA の会員規約 第8条では、BUYMA が用意した画面とは別の方法でアクセスすることや、技術的な制限を回避することが禁止されています。
そのため、この拡張は **BUYMA の出品画面を自動で操作しません**（BUYMA のページには一切入り込みません）。
AI が作るのは「BUYMA の出品画面にそのまま貼れる内容」までで、貼り付け・内容の確認・最後の『出品する』はユーザー本人が行います。
（2026年9月改定の第10条の2「出品支援機能」の、AI が候補を作り出品者が確認して確定する形に合わせています）

### できること

1. **どのサイトでも情報を取る**：商品ページで「この商品の情報を取る」を押すと、ページの中身（本文・JSON-LD・画像の候補）を読み、
   サーバーの AI が商品名・価格（通貨つき）・色・サイズ・仕様・画像を見つけて抜き出します。タオバオ・天猫・1688・韓国や欧米の通販サイトなど、
   サイトごとの設定なしで動きます。
   - タオバオ／天猫は専用の読み取りも使い、全部取れたときは AI を使いません（費用がかからない）。
   - サーバーから仕入れ先サイトには一切アクセスしません。読むのはユーザー本人のブラウザに表示されたページだけです。
   - 読み取りはボタンを押したときだけ、そのタブにだけ行います（`activeTab` + `scripting`）。ふだんはどのサイトにも入り込みません。
2. **確認・修正**：AI の抜き出しはたまに間違えるので、作る前に必ず確認画面を出します。商品名・価格（最低／最高・通貨）・色・サイズ・仕様を直せ、
   違う画像はチェックを外せます。品切れの色やサイズは「（品切れ）」が付いています。
3. **スクショで補う**：取れなかった項目があるときだけ出るボタン。見えている画面を AI で読み取り、足りない項目だけ補います。
4. **BUYMA に貼る内容を作る**：「この内容でAIに出品データを作ってもらう」を押すと、タイトル・商品コメント・価格（円）・カテゴリー候補・
   ブランド・色・サイズ・素材・配送方法を作り、**項目ごとに「コピー」ボタン**を付けて表示します。「全部まとめてコピー」もあります。
   タイトルは文字数を数えながら直せます。価格の内訳、禁止ワードやブランド名の注意、AI からの注意も表示します。
   「保存」で直した内容をサーバーに保存、BUYMA で出品し終えたら「BUYMAで出品済みにする」で履歴の状態を変えます。
5. **画像ZIP**：画像を取り、長い辺を設定のピクセル以下に縮め（拡大はしない）、白背景のJPEGにして
   `taobao_<商品ID>_01.jpg …` の名前で `taobao_<商品ID>_images.zip` に保存します。
   - 画像の置き場所はサイトごとに違うので、タオバオ以外ではボタンを押したときに Chrome が「このサイトの画像を読む許可」を聞きます。
   - タオバオ以外のサイトには商品IDがないので、**URL（?以降を除く）から作った8文字の目印**（例 `0c388e75`）を商品IDにします。
     作る前に商品データに入れてサーバーに送るので、ZIP の画像の名前と管理画面の CSV の画像ファイル名がそろいます。
   - 取れなかった画像があっても番号はずらしません。作っている間はポップアップを開いたままにしてください。

### ログインの連携

1. 設定画面（ポップアップ右上の「設定」）で、サーバーのURL（管理画面のサイトのURL）を入れて保存します。
2. 「ログインして連携する」を押すと、サイトの連携ページが開きます。ログインしてから「拡張機能とつなぐ」を押すと、拡張にログイン情報が渡ります。
3. ログイン情報は期限が近づくと自動で更新されます。更新できなくなったら、もう一度2を行ってください。

拡張は、設定画面で保存したサーバーのURLからのログイン情報だけを受け取ります（ほかのサイトからは受け取りません）。
**本番のドメインが決まったら**、`manifest.json` の `externally_connectable.matches` と `host_permissions` にそのドメインを足してください。

### 使える人の制限（購入した人だけ）

- 商品情報の読み取り・AI の文章作成・画像 ZIP は、ログインして、**お金を払っている人か無料お試し中の人だけ**が使えます
- 判定はサーバー（`web/src/lib/usage.ts` の `isAccountActive`）が行います。解約・支払い停止・お試し終了になると使えなくなります
- 費用がかかる部分（AI の読み取り・文章作成・価格計算・履歴）はサーバーにあるので、拡張機能だけをコピーしても使えません

### 動作確認の方法

1. Chromeで `chrome://extensions` を開き、右上の「デベロッパー モード」をオンにする
2. 「パッケージ化されていない拡張機能を読み込む」で `buyma-tool/extension` フォルダを選ぶ
   （すでに読み込んでいる場合は、更新ボタンを押す）
3. 設定画面でサーバーURLを入れ、「ログインして連携する」→ ポップアップ上部に「メール｜プラン｜残り件数」が出ればOK
4. タオバオ・天猫・韓国や欧米の通販サイトなど、いろいろな商品ページで「この商品の情報を取る」→ 確認画面に商品名・価格・画像が出ればOK
5. 間違いを直して「この内容でAIに出品データを作ってもらう」→ 各項目と「コピー」ボタンが出ればOK
6. BUYMA の出品画面に項目ごとに貼り付けて、内容を確認し、『出品する』を自分で押す →「BUYMAで出品済みにする」
7. 「画像ZIP」でZIPがダウンロードされ、中の画像が開ければOK（タオバオ以外では許可を聞かれます）

### テストの実行

Node.js 18以上と Playwright（Chromium）が必要です。

```bash
cd buyma-tool
npm install --no-save playwright   # 入っていない場合のみ
npm test
```

テストの内容：
- タオバオ／天猫専用の読み取り（新しいタオバオ・古い天猫・商品ページでないとき）
- どのサイトでも使える読み取り（韓国の通販サイト＝JSON-LD あり・ヨーロッパの通販サイト＝JSON-LD なし：
  JSON-LD を取ること、本文からスクリプト・メニュー・ヘッダー・フッターを除くこと、本文を上限で切ること、
  画像の候補を絶対URL・重複なし・アイコンや小さい画像やdata:を除いてそろえること、URL の目印）
- 確認・修正画面（専用読み取りと AI の結果の使い分け、品切れ・色・サイズ・仕様の行き来、外した画像、商品IDの目印、まとめてコピーの文章）
- ZIP（CRC32の値、`unzip -t` か Python の zipfile で開けること、中身が一致すること）
- APIの道具（401のときに1回だけ更新してやり直す、期限前の更新、上限のエラー文、更新できないときのログアウト、解約時の扱い、設定の範囲）
- 拡張機能そのものを Chromium に読み込めること（manifest の誤りがないこと、画面にエラーが出ないこと、BUYMA の自動操作が入っていないこと）

### 注意

テストの見本ページは、各サイトのページの作りを手で再現したものです。
本物のページで上の「動作確認の方法」を行い、取れない項目があれば、そのページを保存して `tests/fixtures/` に加え、
`page-reader.js`（どのサイトでも）や `extractor.js`（タオバオ／天猫）を直してください。
